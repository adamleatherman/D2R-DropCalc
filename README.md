# D2R Drop Calculator (local, offline)

Static page + vanilla JS, Python standard library only. No framework, no CDN, no build step apart from parsing the game tables.

## Usage

```
python build.py [path-to-excel-folder]     # default C:\Users\thein\D2R-excel  -> writes data.json (re-run after each patch)
                                           # the folder must come straight from the game archive: root = RotW tables, base\ = LoD, hd\desecratedzones.json
                                           # (current extract: build 3.3.93847). Sanity check: most root tables must differ from their base\ copy (see Game modes)
run.bat                                    # builds data.json if missing, starts http.server on :8000, opens the browser
python test_engine.py                      # validation (starts its own server + headless Edge/Chrome)
```

Files: `build.py` (tables -> `data.json`), `engine.js` (all math, no DOM), `app.js` + `index.html` (UI), `worker.js` (Web Worker for the affix search), `test.html` + `tests.js` + `test_engine.py` (validation). The game folder is only read.

Global selectors (saved in localStorage): game mode (LoD / RotW), difficulty, players in game, partied players nearby (including you), MF %, terror zone on/off + character level + herald tier (RotW, Hell, terror zone only), ladder/non-ladder, act.

* **Tab 1, item search** - autocomplete over bases, runes, unique and set items. Every monster/rank/area/difficulty that can drop it, with mlvl, P(base), P(magic), P(rare), P(set), P(unique), P(target), "1 in N kills", kills per run, per-run chance and "1 in N runs". The "Percentiles" selector (Off / Kills / Runs, saved in localStorage) adds six columns with the kills or runs needed to have found it with 25/50/75/90/95/99% probability: `ceil(ln(1-q) / ln(1-p))` (`Engine.trialsFor`). Click headers to sort; filter by text, rank, difficulty, act. For a unique/set item P(target) is the chance of that exact item.
* **Tab 2, affix finder** - pick a base or "Any <base type>", magic or rare, add conditions (stat + minimum value; the stat list is built from the affixes that can actually roll on that base). Ranked list by P(base) x P(quality) x P(all conditions at that affix level). Magic is exact enumeration, rare is a seeded Monte Carlo (50k/200k/1M rolls per distinct affix pool, in a Web Worker). Shows the minimum affix level / monster level for each condition. Choosing a single area ranks by per-run chance.

## Formulas implemented

**Treasure classes** (`engine.js: dist`). Entry probability is Prob / (sum Prob + NoDrop'). Positive Picks k: P(leaf at least once) = 1-(1-s)^k, where s is the per-pick chance (nested TCs multiply). Negative Picks: guaranteed drops, entry i is rolled |Prob_i| times in order until |Picks| rolls are used. The Unique/Set/Rare/Magic factors of nested TCs combine with **max** (decompiled `TreasureClassDropper`, PureDiablo). Monster TC upgrade: highest TC of the same `group` with `level <= mlvl` (top-level TC only; bosses are not upgraded unless terrorized, as in the data guide). Names like `weap72`/`armo66`/`bow45`/`mele30` are generated: all spawnable items of that item type (including child types) whose qlvl is in `(N-3, N]`, weighted by the `Rarity` column of ItemTypes.txt for the item's first type (`type`), values <= 1 forced to 1 (quest items excluded). There is **no check of the base item's qlvl against the monster level**: a level-81 Hell Bovine can drop Archon Plate (qlvl 84) via `armo84`. Nested TCs are fetched with level 0, so only the top-level TC is group-upgraded. Source: D2MOO `DATATBLS_CreateItemTypeTreasureClasses` (MonsterTbls.cpp), `DATATBLS_GetTreasureClassExRecordFromIdAndLevel`, `D2GAME_DropTC_6FC51360` (Items.cpp). `ConditionCalc` is not evaluated (no row uses it) and of `DropConditionCalc` only `cond('Difficulty', normal|nightmare|hell)` is understood (the six PreCrafted Sunder uniques; any other expression would exclude the row); `first/lastLadderSeason` are honoured with `CONFIG.currentSeason = 99` (a ladder-only window that has ended opens the item to non-ladder, so with the current tables the ladder selector changes nothing).

**Per-kill drop cap** (`CONFIG.dropCap = 6`, `engine.js: dist`). The game's drop routine (decompiled `TreasureClassDropper`, https://gist.github.com/SeanSullivan86/e912b40bb85f9822b9ef507d91534c88) stops a kill after 6 items (`if (*itemCount >= maxItems) return;`). This limit is hard-coded in the game, not in the tables, and is assumed to still be present in 3.3. Drops happen in order (depth-first, picks in sequence, negative-Picks entries in listed order); gold, potions, scrolls and keys count, non-item entries (quest flags) do not. It matters for Duriel (about 18 items uncapped, roughly 3x overstated) and a few percent for Countess, Mephisto, Diablo, Baal, Andariel, more with more players. It is computed exactly: a TC is a linear map on the number of items dropped so far (0..6); sequences multiply the matrices, a pick is a mixture, and per leaf the matrix of "this leaf not produced" is kept so P(leaf at least once) = 1 - (row 0 of that matrix summed). TCs whose maximum possible item count is <= 6 use the plain formula. `CONFIG.dropCap = null` (or 0) reproduces the uncapped numbers exactly.

**NoDrop with players**: `NoDrop' = floor(Items / (1/(NoDrop/(NoDrop+Items))^N - 1))`, `N = nearbyParty + floor((players - nearbyParty)/2)`.

**Item quality** (`quality`): per base, checked Unique > Set > Rare > Magic > Superior > Normal > Low, each failure falls through.
Exact game integer math (D2MOO `D2GAME_DropTC_6FC51360`, Items.cpp; C division truncates toward zero): `nLevelDiff = mlvl - qlvl`; `p = (Ratio - nLevelDiff/Divisor) << 7` (the division comes first and is truncated); with MF != 0, `D = MF + 100`, `p = 12800*(Ratio - nLevelDiff/Divisor)/div` where `div = D` for magic and, for D > 110, `50*(5D-500)/(D+150)+100` (unique), `100*(5D-500)/(D+400)+100` (set), `200*(3D-300)/(D+500)+100` (rare) - equal to `100 + trunc(MF*dim/(MF+dim))` with dim 250/500/600 (`CONFIG.mfDim`), cutoff MF > 10 (`CONFIG.mfThreshold`; the data guide's "exceeds 110%" counts the `item_magicbonus` baseline of 100); `p = max(p, Min)` (unique/set/rare/magic); `p -= p*TCfactor/1024`; success if `p <= 0` or `rand(p) < 128`, i.e. chance `= 128/p` (1 if p <= 128). Superior/normal use `HiQuality`/`Normal` with their divisors, no MF, no Min, no TC factor; failing normal gives low quality. MF is applied to unique/set/rare/magic only. itemratio row: Version 1, Uber (exceptional/elite) and Class Specific flags. Unique success with no eligible unique (spawnable, not disabled, lvl <= ilvl, ladder rules) becomes rare (magic if the type cannot be rare); set success with none becomes magic. Chance of one specific unique/set = quality chance x rarity / sum rarity of the eligible ones for that base. Item types flagged "Magic" (rings, amulets, jewels, charms) are always at least magic; "Normal" types (runes, gems, potions) are always normal.

**Monster level**: Normal = monstats `Level`; Nightmare/Hell regular monsters = the area's `MonLvlEx(N/H)`; act bosses = monstats `Level` per difficulty (Andariel 75, Mephisto 87, Diablo 94, Baal 99 in Hell); super uniques = the area level of their (hand-mapped) area (Normal uses the class monster's `Level`) **plus the unique bonus +3** (Hell Pindleskin 86, Hell Countess 82, Normal Rakanishu 8, Normal Cow King 31; in a terror zone `tzLevel(...) + 3`, which may exceed the zone max). Act bosses get no bonus. Champions +2, uniques +3, unique minions +3 (`CONFIG`). Radament, The Summoner, Nihlathak and Griswold are both super uniques and act bosses in the tables; only the act-boss row is kept (no bonus). Terror zone: `mlvl = max(base, clamp(clvl + boost_level, bound_incl_min, bound_incl_max))` per difficulty from `desecratedzones.json` (Hell: 70..96, +2), then the rank bonus is added and may exceed the max; the `TreasureClassDesecrated*` / super unique `TC Desecrated` columns replace the normal TC when present. Only levels listed in the zone file are flagged as terror-zone areas.

**Affix level and eligibility**: `ilvl = max(mlvl, qlvl)`; `alvl = ilvl + magic_lvl` if the base has one, else `ilvl - floor(qlvl/2)` (or `2*ilvl - 99` for very high ilvl), capped at 99. Affix rows used: version >= 1, frequency > 0, spawnable = 1 (rare = 1 for rares), `level <= alvl`, `maxlevel` blank or >= alvl, the base's type or any parent type (Equiv1/Equiv2) in `itype`, none in `etype`. Class-tagged affixes can appear on any matching type, but a class-specific base only takes its own class. Weighted by `frequency`, never two with the same `group`. Roll = uniform in min..max. `automagic.txt` rows are applied for bases with an `auto prefix` group (one eligible row by frequency, level-gated). Conditions are checked per stat label (`properties.txt` tooltip + parameter); two conditions can be met by two different affixes, contributions of two affixes to the same stat are not added.

**Per-run estimate (rough)**: packs = SizeX*SizeY * `areaFill`(0.4) * MonDen/100000; each pack is one monster type chosen by `Rarity` share among the area's monster list (mon for Normal, nmon for NM/Hell), size = average of MinGrp/MaxGrp. Unique/champion packs = average of MonUMin/MonUMax, 20% champion packs (3 champions each), 80% unique packs (1 unique + PartyMin/PartyMax minions, default 2). Bosses and super uniques = 1 kill per run. These constants live in `CONFIG.run`; treat the per-run columns as order-of-magnitude.

## Game modes

`D2R-excel\base\` is the **Lord of Destruction** mode (not classic) and the root folder is **Reign of the Warlock**. 38 of the 91 tables differ between them, 53 are byte-identical. The differences are mostly new content or retuned values: `treasureclassex` (+220 rows: Herald, Ancient Statue, Worldstone Shard, Uber TCs), `uniqueitems` (+12 rows: PreCrafted/Crafted Sunders, the Ars grimoires; new `disableChronicle` column), `monstats` (herald TC columns, Uber Ancients), `levels` (+Colossal Summit), `misc`/`itemtypes` (+1 row each), `cubemain` (+72), `armor`/`automagic`/`weapons`/`runes`/`sets`/`setitems`/`magicsuffix`/`properties` and skill/state/sound tables (value changes), and a few cosmetic ones. The calculator reads the RotW values everywhere; `build.py` stores only the two LoD overrides as `spl` flags in `data.json`. (An earlier version of this README said only `armor.txt` and `automagic.txt` differ; that was wrong: it came from a bad extract in which 36 root tables were copies of the LoD ones.)

* `armor.txt`: the 15 Warlock grimoires (`wa1`..`waf`, type `grim`) are spawnable only in RotW. In RotW they join the generated `armoN` pools and dilute the other armor bases (a mid-level base such as `xhl` has about 4% better per-kill odds in LoD, checked against an independent bracket-weight calculation).
* `automagic.txt`: the 8 grimoire auto-mods (group 306) exist only in RotW.

`CONFIG.gameMode` (`'lod'` | `'rotw'`, default `'rotw'`; UI selector "Game mode") picks armoN pool membership, the automagic set, the search index, the Tab 2 base list and the `desecratedzones.json` section (`expansion` for LoD, `rotw` for RotW; the Normal/Nightmare/Hell bounds are identical). Grimoires and their affixes never appear in LoD. `Engine.setMode()` clears the affected caches.

## Heralds (RotW, Hell, terror zone on)

Data-driven (`desecratedzones.json` -> `rotw.hell.defaults.herald_tiers`): five tiers with `herald_treasure_class_level_boost` 0/3/6/9/12 (data guide: "boost to the treasure class level of a Herald... not a boost to the item level dropped"), minion counts, unique mod counts, HP/damage boosts and the logistic spawn-chance constants.

* **Herald TC**: monstats `TreasureClassHerald(H)` (465 monsters, e.g. `skeleton1` -> `Act 1 (H) Herald A`; the Normal/Nightmare columns are empty, heralds are Hell only). `build.py` exports it as `m.tc[2].hr`. One herald row is created per area monster type with `CannotHerald` not set; mlvl follows the terror-zone unique rule (+3).
* **Group upgrade**: the herald TCs are group 41 (`Act N (H) Herald A-C`, levels 67..96, Picks -6), upgraded at `mlvl + herald_treasure_class_level_boost` like any top-level TC. **Data quirk**: the five `Ancient Statue 1-5` TCs are also group 41, all at level 92, so an unrestricted upgrade landing on 92 would resolve to a statue TC (ties go to the last in file order, `Ancient Statue 5`). Nobody has observed a herald dropping a statue piece, so heralds are restricted to the Herald TCs (`upgradeTC(..., only)`). This is observed behaviour, not something the tables say. The tier boost only matters while `mlvl + boost` is below 96, the level of `Act 5 (H) Herald C`.
* **Tier gating of the extra item picks** (`CONFIG.heraldExtraByTier = [null, null, '1 Extra', '1 Extra', '2 Extra']`). Each top-level herald TC lists `Herald Item X` x2, `Herald Item X - 1 Extra` x1 (Picks -1: one more item pick), `Herald Item X - 2 Extra` x1 (Picks -2: two more) and `Cpot` x2; each `Herald Item` pick holds `Sunder Charms` at 2/407. Taking every entry (5 item picks) does not match the published odds for PreCrafted Flame Rift from heralds (1:342 tier 1-2, 1:228 tier 3-4, 1:171 tier 5); 1-(1-p)^n with p = (2/407)(30/101) and n = 2, 3, 4 item picks does exactly. So the game gates the extras by tier: tiers 1-2 drop only the base entries, tiers 3-4 add `- 1 Extra`, tier 5 adds `- 2 Extra` (not both). The gating is hard-coded (not in the tables), verified against the published odds; it is also what the 3.2 note "tier 3 and 4 have twice the increased chance, tier 5 three times" amounts to, so the old "herald bonus path" with an unknown base chance (`heraldSunderBonusBase`, the "Herald Sunder bonus base %" input) is gone. The engine gives 1 in 342.8 / 228.7 / 171.7 (1 player, table path; the 6-item cap does not change them, the MF path through unique grand charms adds only ~5e-6 to 1e-5 per kill). Herald Sunder chances do not scale with players (the Herald Item TCs have NoDrop 0).
* `Herald Charm 1-10` TCs exist but nothing references them (probably the hard-coded "something desirable" fallback); they are not modelled and not counted as a source.
* **Latent Sunder Charms: two paths** (separate columns in Tab 1 when you search a Sunder unique; the six uniques are the `PreCrafted ...` rows of `uniqueitems.txt`). Sunder type weights equal the `Sunder Charms` TC weights 30/30/20/12/6/3.
  * **(a) Table path** - the `Sunder Charms` TC (Picks 1, ladder season 2/2) included by every desecrated champion/unique/super/boss TC and by the `Herald Item` TCs. Pure data; scales with players where the enclosing TC has NoDrop.
  * **(b) MF path** - the PreCrafted Sunders are also `spawnable=1` unique grand charms (`cm3`, lvl 75, rarity 1, `DropConditionCalc` `cond('Difficulty', hell)`), so a unique grand charm roll in Hell at ilvl >= 75 can pick one (weighted by rarity: 1 each against 15 for Gheed's Fortune and the other unique grand charms). This replaces the earlier hard-coded rule (`sunderMf*` constants, from the 3.2/3.3 patch notes); the tables now state it themselves.
* **Herald quality**: 3.2 "slightly reduced the chance for Heralds to drop Unique, Set, and Rare"; 3.3 "increased the chance of dropping Rare quality and higher from Herald Tiers 3+". Sizes unknown, so `CONFIG.heraldQualityAdj` = `{t12: {unique, set, rare}, t3plus: {rarePlus}}` defaults to 1 (no-op) and applies to herald rows only. The UI marks the herald quality columns as unadjusted.
* Not modelled: when a herald spawns (zone completion logistic), so there is no per-run herald odds; the "something desirable" fallback.

Sources: https://diablo2.io/post4136083.html (datamine thread), https://www.icy-veins.com/d2/reign-of-the-warlock-endgame-changes-for-diablo-ii-resurrected, https://news.blizzard.com/en-us/article/24266710/diablo-ii-resurrected-ptr-3-2-now-live, and the data guide pages `desecratedzones` and `monstats` (`TreasureClassHerald`).

## Items named explicitly in treasure classes

`spawnable=0` items and uniques are dropped only when a TC names them. The engine treats any item code or unique/set id named in a TC as a leaf (`dist`), and the Tab 1 search index lists every such item (`searchIndex`: `explicitI` for items, `explicitU` for uniques). Per-kill chances come straight from the TC walk, including the drop cap:

* **Colossal Ancient statue pieces** `ua1`-`ua5` ("Uber Ancient Summon Material Act N", `spawnable=0`): named by the `Ancient Statue 1-5` TCs (e.g. `Ancient Statue 1` = ua1 18, ua2 1, ua3 1), which the Hell act boss TCs and their Desecrated variants reference (`Andarielq (H)` has `Ancient Statue 1` at Prob 2).
* **Worldstone Shards** `xa1`-`xa5` (`spawnable=1`, level 75, rarity 14): from the `Act N Worldstone Shard Parent [Citem|Uitem] A`, `Act N (H) Herald Item Shard` and `Act N Terrorize Act Consumable` TCs reached from champion, unique, super unique and herald TCs. The "Act N" in these names is **not** the monster's act: `Act N Terrorize Act Consumable` is a pick of `xa1`-`xa5` biased towards `xaN` (weight 5 for the own shard, 1-3 for the others), i.e. N is the shard type. The monster act to shard parent mapping in the Hell TCs is a permutation (`Act 1 (H) Citem A` -> `Act 3 ... Parent`, 2 -> 4, 3 -> 5, 4 -> 2, 5 -> 1); the engine just follows the tables.
* **Keys** `pk1`/`pk2`/`pk3` (Terror, Hate, Destruction): `Countess Item (H)` / `Summoner (H)` / `Nihlathak (H)` and their Desecrated variants.
* **Uber Ancients**: the Hell-only monsters `colossal1-3` ("Ancient Barbarian 1-3", boss, `Level(H)` 110, Colossal Summit, level 137) have `TreasureClass(H)` = `Uber Talic` / `Uber Madawc` / `Uber Korlic` (group 40, level 110, Picks 1, NoDrop 0): one of two `spawnable=0` uniques each (Defender's Bile/Fire, Guardian's Light/Thunder, Protector's Stone/Frost), 50% per kill each before the cap. They are in `BOSS_AREA` and have no Normal/Nightmare row. The older `ancientbarb1-3` rows have no TC and stay skipped.

## Validation (`python test_engine.py`)

1. Independent Python re-implementation reading the raw `.txt` tables: the engine's expected unique/set/rare/magic items per kill match to 1e-9 for Hell Andariel, Mephisto, Countess, Duriel and Baal at 0 and 300 MF with 1 and 3 players, and the chance of specific items matches.
2. Published figures: effective MF for 200% MF = 111 (PureDiablo example), Hell Baal unique `p` for a qlvl-85 base at 200% MF = 938 (page says 939; re-checked with the exact D2MOO integer formula, still 938, so the page rounds differently; base not stated); "Players X" NoDrop worked example 60/22/11/5 reproduced exactly; Hell Countess: 5 item rolls with NoDrop 19 and 3 rune rolls with NoDrop 5 vs Prob 15 give P(no rune) = 1/64 as the wiki states. Item roll NoDrop share is 19/68 not 19/67 because D2R 3.3 added a `pk1` entry.
3. Mismatch, explained: the only published Hell Countess Ist figure I could find (1 in 287, 1.10-era forum post) differs from the current tables (1 in 236; 1 in 238 from the rune table alone; unchanged by the correct tables). The engine equals hand arithmetic from the current tables.
4. Not reproduced: a PureDiablo forum thread says /players 3 gives about +9.5% drop chance on Mephisto; the engine gives +19% more items per kill for N=2. The thread was not retrievable (403), so its assumptions are unknown.
5. Engine outputs to compare with Silospen's drop calculator (dropcalc.silospen.com, which could not be scraped from here): (uncapped figures, before the drop cap) Hell Mephisto, 1 player: Harlequin Crest 1 in 1713 at 0% MF, 1 in 726 at 300% MF; Tal Rasha's Horadric Crest 1 in 491 / 1 in 190; Hell Andariel: Harlequin Crest 1 in 2360 / 1 in 1000; Hell Countess: Mal 1 in 157, Ist 1 in 236 (1 player). With the old (wrong, LoD-copy) tables the same checks gave Mephisto HC 1 in 1678 / 711, Tal Rasha's 1 in 481 / 187, Andariel HC 1 in 1654 / 701 (the Andariel figure moved most: the real `Andarielq (H)` differs); the 4463 / 1891 / 425 / 165 / 4402 / 1867 quoted here previously could not be reproduced by the current test (`Mephisto Hell MF0: P(Harlequin Crest) per kill`) either and are dropped.

6. Drop cap: the engine's per-leaf probabilities are compared with an independent seeded Monte Carlo of the raw TC tree (6-item cap) for Duriel (H), Duriel (H) Desecrated D, Mephisto (H) Desecrated D, Countess (H), Andarielq (H) and Andarielq (H) Desecrated H at 1 and 8 players (within 5 sigma). The legacy comparisons in item 1 run with the cap off.

7. Table-driven drops (new with the correct tables): Hell Andariel -> `ua1` etc. (engine vs the independent reference, uncapped), a Hell champion -> `xa1`, keys `pk1`-`pk3` from Hell Countess / Summoner / Nihlathak, the six Uber Ancient uniques (1/2 per kill), Ars Al'Diablolos/Tor'Baalos/Dul'Mephistos having sources, and the search index listing all explicitly named `spawnable=0` items. The Equip-branch Monte Carlo pins for Duriel/Mephisto (H) Desecrated D moved from 6.41 -> 2.02 / 4.50 -> 4.31 (wrong tables) to 6.27 -> 1.97 / 4.37 -> 4.20.

No authoritative per-kill unique/set tables for Hell Mephisto/Andariel were retrievable offline, so the "match" for those is against the independent re-implementation, not against a website.

## Assumptions and limitations

* Super unique and boss locations are not in the tables; `SU_AREA`/`BOSS_AREA` in `build.py` are hand-written, with `SU_AREA` cross-checked against the Arreat Summit act 1-5 super unique pages and PureDiablo's superunique overview (source noted per changed row). Their mlvl depends on that area. Rows that exist in `superuniques.txt` but never spawn (Winged Death, The Tormentor, Taintbreeder, Riftwraith the Cannibal, Axe Dweller, Anodized Elite, Vinvear Molech, Magma Torquer, Blaze Ripper, Flamespike the Crawler) are listed in `SU_UNUSED` and are not sources. Baal's five minion waves (`Baal Subject 1-5`) are mapped to the Throne of Destruction. Ancient Kaa is placed in Tal Rasha's Tomb (66); Stormtree in Lower Kurast (79). The quest Ancients (`ancientbarb1-3`, Talic/Madawc/Korlic of the Arreat Summit fight) have no drop TC in the tables (every `TreasureClass*` column in `monstats.txt` and `TC*` column in `superuniques.txt` is empty) and are skipped; the Uber Ancients are separate monsters (`colossal1-3`, see above) and are included. `uniqueitems.txt`'s new `disableChronicle` column and the Crafted (non-PreCrafted) Sunder rows are not used.
* **Quest drop** (sidebar checkbox, setting `quest`, off by default): act bosses switch to their `TreasureClassQuest` / `(N)` / `(H)` TC. In the game (D2MOO `D2Game/src/MONSTER/MonsterMode.cpp`, after the normal/champ/unique TC is picked) the quest TC replaces it when monstats `TCQuestId` is set, `TreasureClassQuest` is non-empty, and the killing player (or a minion's owner) has not completed that quest, has no reward pending, and has not reached checkpoint `TCQuestCP`. So it applies to the first kill while the quest is open (Mephisto/Diablo/Baal checkpoint 0, Duriel 5, Andariel 1). Monsters with it in this data: Andariel, Duriel, Mephisto, Diablo, Baal. Quest TCs drop no gold/junk and have Rare=1024 (rare-or-better) and Unique/Set 993. Andariel's normal `TreasureClass` already is `Andarielq` in every difficulty, so the toggle changes nothing for her (D2R always uses it). Bosses keep their own TC (no group upgrade) unless terrorized, also for quest TCs. **ASSUMPTION** (`CONFIG.questOverridesTz = true`): D2MOO's quest check runs last and overrides whatever TC was chosen, but D2MOO is 1.10 (no desecrated TCs), so D2R's behaviour in a terror zone is unknown; the quest TC is assumed to override the desecrated TC too. Andariel's desecrated columns are `Andarielq ... Desecrated`, hinting that the desecrated column may be used as-is in TZ; set the flag to `false` for that.
* Unique minions use the normal TC at mlvl+3; Reign of the Warlock extras (herald minions/unique mod counts, always-unique mods) and the +25% terror zone XP are ignored. `CONFIG.tzMode` can select the rotw bounds (identical numbers in this file).
* `QuestFlag`, `ConditionCalc`, `DropConditionCalc` ignored; ladder season gating is generic but has no effect with the current rows.
* Item names are the table `name` columns (no localized strings in the data); monsters are shown by their `NameStr` key.
* Rare Monte Carlo has sampling noise for very small probabilities (about 1/sqrt(hits)); raise the roll count. Magic is exact. The same affix cannot be satisfied by summing two affixes, and "chance to cast" style stats are matched on label only.
* Per-run counts are a rough model (see above), and ignore waypoints/route length, wandering monsters, shrines, and that a real clear never kills everything.
* Warlock (Reign of the Warlock) skill-tab affixes use generic names.
